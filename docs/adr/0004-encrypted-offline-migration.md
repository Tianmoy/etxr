# ADR-0004: 使用离线加密包迁移 ETXR 状态

- 日期：2026-08-28
- 状态：已接受

## 背景

ETXR 的完整节点状态包含用户 UUID、协议密码、Reality 私钥、EasyTier 密钥、主从配对
信息和统计数据。用户需要在重装系统或更换服务器时迁移这些内容，但不希望保留 SSH
传输通道，也不能把敏感状态以明文压缩包保存或发送。新服务器的域名、证书位置和 nginx
环境可能与旧服务器不同。

## 决策

提供显式的离线导出和导入流程。导出只打包固定白名单中的 `state.json`、流量与域名统计、
以及主从配置签名密钥。内容使用 AES-256-CTR 和 PBKDF2-HMAC-SHA256 加密，并对元数据和
密文计算独立的 HMAC-SHA256。导入必须先完成容器白名单、大小、HMAC、密码、JSON 和状态
语义检查，之后才允许应用配置。

TLS 证书、证书私钥、宝塔网站配置、nginx 完整配置、生成配置和程序二进制不进入迁移包。
导入时重新询问域名、连接地址和证书路径，并根据新服务器是否安装宝塔选择 nginx 模式。
配置应用失败时恢复目标服务器导入前的 ETXR 状态。
默认只允许导入到尚未初始化 ETXR 的目标机；覆盖已有配置必须显式使用 `--force`，以避免
旧域名的 nginx 管理文件与迁移后的配置同时残留。

## 备选方案

- 通过 SSH 直接复制目录：需要长期保留跨服务器 SSH 授权，不符合用户要求。
- 明文 tar 包：操作简单，但会暴露协议密钥、用户凭据和配对密钥。
- 连同证书一起迁移：减少一次配置步骤，但扩大私钥泄露范围，也容易把旧域名证书错误部署到新机。

## 后果

- 正面影响：迁移文件可以离线传递，错误密码或内容篡改会在解密和应用前被拒绝。
- 负面影响：用户必须妥善保存至少 12 个字符的迁移密码，并在新服务器单独部署证书。
- 风险与后续：已配对从服务器仍保存主服务器控制域名；主服务器迁移时应保留原域名，否则需要重新配对。
