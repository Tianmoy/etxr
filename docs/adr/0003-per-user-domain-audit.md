# ADR-0003: 按用户聚合访问域名

- 日期：2026-08-05
- 状态：已接受

## 背景

ETXR 已能通过 Xray Stats API 统计每个用户的上下行字节数，但该 API 不包含访问目标。
解析 Xray 文本日志会依赖非结构化格式，并且无法稳定关联嗅探后的域名、用户和入口。
主从部署还要求从服务器主动上报结果，不能新增公网管理端口。

## 决策

使用 Xray 路由规则的本机 Unix Socket Webhook，把结构化路由事件发送给
`etxr-dataplane auditor`。审计器只接受本机 Socket 请求，根据认证邮箱映射 ETXR 用户，
优先记录 Xray 嗅探后的 `routeTarget` 域名，并按用户聚合连接次数、首次访问和最近访问时间。

审计功能默认关闭。启用时默认保留最近 30 天内出现的域名，每个用户最多保留 500 个，
超限时淘汰最久未访问的记录。持久化文件权限为 `0600`，不保存完整 URL、请求内容或客户端
IP。无法从 IP 连接或加密握手中识别域名时只累计“未识别连接”数量。

从服务器通过现有 HTTPS/WSS 控制通道上报聚合结果，主服务器按用户 UUID 和独立的
`domain_epoch` 汇总。清空历史通过更新 `domain_epoch` 自动传播到所有从服务器。

## 备选方案

- 解析 Xray access/error 日志：格式非结构化，嗅探域名与认证用户难以可靠关联。
- 只在限速 SOCKS 代理统计：只能覆盖有限速用户，并且远程出口看到的是中继地址。
- 记录完整请求日志：信息过多、存储无界，并增加不必要的隐私风险。

## 后果

- 正面影响：XHTTP、Reality 和 Hysteria2 使用同一套结构化统计，不新增公网端口。
- 负面影响：每个新连接会增加一次本机 Unix Socket HTTP 事件；功能默认关闭以避免无意开销。
- 风险与后续：只能统计 Xray 能识别的域名；IP-only、ECH 或其他不可嗅探流量会计入未识别数量。
