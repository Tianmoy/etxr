# ADR-0002: 按用户控制节点访问权限

- 日期：2026-08-04
- 状态：已接受

## 背景

一个 ETXR 用户原先默认出现在全部 XHTTP、Reality 和 Hysteria2 入口中。已有的
`users[].routes` 只过滤本机 XHTTP 路线，无法表达从服务器独立入口，也不会限制
Reality 和 Hysteria2。菜单即使增加节点开关，如果运行配置、集中订阅和主从下发
继续使用不同规则，界面显示的权限也不会真实生效。

## 决策

为用户增加 `enabled_nodes` 数组，并使用以下稳定节点键：

```text
入口机器名/xhttp/线路名
入口机器名/reality/Reality名称
入口机器名/hy2
```

主服务器从本机状态和从服务器回报的公开入口快照汇总节点，菜单按编号让用户多选。
Xray 客户列表、sing-box Hysteria2 用户、单用户限速路由和集中订阅统一依据相同节点键
过滤。`enabled_nodes` 随用户配置通过现有 WSS/HTTPS 控制通道下发，从服务器只执行
与本机名称匹配的权限。

新用户必须明确选择至少一个节点。已有用户可以选择空列表以关闭全部节点，也可以
随时重新开启。只有用户获准使用 Hysteria2 节点时才需要生成 Hysteria2 登录密码。
新增协议或从服务器不会自动加入新用户的权限列表。

为避免升级导致现有连接中断，缺少 `enabled_nodes` 的旧用户以及显式配置
`enabled_nodes: ["*"]` 的用户继续拥有全部节点。旧的 `routes` 字段暂时保留，用于
兼容已有命令行参数和状态文件，但不再作为跨协议授权来源。

## 备选方案

- 扩展 `routes` 同时表示协议和机器：旧字段语义是 XHTTP 线路名，复用后容易产生名称
  冲突，也无法稳定区分 Reality 与 Hysteria2。
- 按协议设置三个布尔值：实现简单，但不能在同一协议的多个主从入口之间分别授权。
- 每台从服务器维护独立用户权限：节点隔离明确，但会破坏主服务器统一管理和集中订阅。

## 后果

- 正面影响：每个用户只会出现在被授权节点的服务端配置和订阅中；主从权限保持一致。
- 负面影响：节点改名会产生新的节点键，管理员需要重新选择该节点；离线且从未回报过
  入口快照的从服务器独立入口暂时不会出现在选择列表中。
- 风险与后续：`["*"]` 是兼容模式，会自动包含未来节点；待所有部署完成显式迁移后，
  可在新的 ADR 中决定是否移除该模式和旧 `routes` 字段。
