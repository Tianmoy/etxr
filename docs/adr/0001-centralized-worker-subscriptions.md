# ADR-0001: 主服务器集中生成订阅

- 日期：2026-08-03
- 状态：已接受

## 背景

主服务器和从服务器都可以提供 XHTTP、Reality 和 Hysteria2 客户端入口。用户与
限速配置由主服务器统一管理，但原有实现会在每台机器本地生成订阅，用户需要分别
登录服务器获取链接，也容易拿到不同步的节点列表。

## 决策

从服务器通过已有的出站 WSS/HTTPS 控制通道，每分钟向主服务器回报经过裁剪的
公开入口快照。主服务器校验快照中的节点名称、地址、端口、Path 和协议字段，再把
有效入口合并到主服务器生成的用户订阅中。

从服务器关闭订阅生成和 nginx 订阅 location。用户只从主服务器获取订阅。
从服务器不回报 Reality 私钥、证书私钥、SOCKS5 用户名或 SOCKS5 密码。

订阅节点名称只使用机器名称、可选出口名称和协议，不包含域名。

## 备选方案

- 每台服务器分别生成订阅：实现简单，但用户需要管理多个链接，节点列表容易不一致。
- 主服务器通过 SSH 拉取从服务器配置：依赖长期 SSH 凭据，与现有主动控制通道重复。
- 把完整从服务器状态上传到主服务器：便于复用，但会传输不需要的私钥和出口凭据。

## 后果

- 正面影响：用户只有一个订阅入口；从服务器无需暴露订阅 URL；现有控制通道可复用。
- 负面影响：从服务器入口修改后，主服务器订阅最多延迟一个上报周期更新。
- 风险与后续：离线从服务器的最后一次有效快照会保留，需要通过运行状态判断节点是否可用。
